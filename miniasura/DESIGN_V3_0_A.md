## §0 审计事实（改之前先把现状钉死）

| 事实 | 位置 | 对本期的约束 |
|---|---|---|
| 装备加成**唯一聚合点**是 `gear.totals()` | `gear.py:176-222` | 宝石与套装都必须汇进这一个函数，**不许**在 engine 里另开一路加法 |
| `apply_gear()` 只消费 `totals()` 与 `passive_totals()` | `engine.py:52-64` | 攻击 = `(player_attack + tot.atk) × pas.atk_mult`；HP = `base + (lv-1)×per_lv + tot.hp`；def/dodge/hit/mitigate/crit 全来自 tot+pas |
| `totals()` 有**词条白名单**，遇未知 key 直接 `raise ValueError` | `gear.py:203-204`、`216` | 新增宝石/套装词条必须同时改白名单，否则运行时炸——这是好事，等于强制登记 |
| 装备品质 0/1/2 = 白/蓝/紫，词条数 `AFFIX_COUNT = (0,1,2)` | `gear.py:20-21` | 孔位数天然可以复用同一套"按品质分级"的心智模型 |
| 玩家属性**没有任何加点系统**：升级只抬 level，`player_attack()` 公式住 `battle.lua` | `engine.py:47-49` | 属性点不能改 lua 公式（改公式等于改全部基线），只能以 flat 加成并入 `tot.atk` |
| 背包窗 `gui_bag.py` 已 190 行，且是"列表+详情"单页结构，无页签 | `gui_bag.py:11-190` | 三套新界面**不能**往 bag 里塞，必须新开窗 |
| 存档写档唯一出口 `save.write_raw()`，`daily.touch` 已挂在这里 | `save.py:128-134` | 新增字段走同一出口 + `_migrate` 补默认，不另开写档路径 |
| `[bag] capacity = 20` | `game.ini:41-43` | 宝石碎片若也占背包格，20 格会被迅速挤爆 → 见 G3 |
| CLI 全通基线 **Lv.25 / 金币 798**，写在多个 smoke 断言里 | `smoke_v28.py:176`、`smoke_v29a.py:196`、`smoke_v29b.py:204` | 本期数值设计的**硬约束**见 §6 |

**一句话结论**：本期所有新数值只有两个合法落点——`gear.totals()` 的聚合（战斗面板）和 `apply_gear()` 的叠加顺序。任何绕开这两处的"顺便加个攻击"都会让门禁与基线失守。

## §1 范围

做：
1. **宝石**：碎片 → 合成 → 镶嵌到装备孔位 → 拆卸回收。
2. **套装**：2 件 / 4 件套效果，按穿戴的同套件数判定。
3. **属性点**：升级得点、自由分配、**免费无限洗点**。

不做（写死，防蔓延）：
- 不做练功房 / 挂机收益（roadmap §7 backlog）。
- 不做怪物数值随玩家变强而自动膨胀。
- 不做宝石合成失败率、不做拆卸损毁/收费、不做洗点代价（本地单机，惩罚只制造读档）。
- 不做套装掉落专属池（沿用现有 loot 表，只是掉落时多掷一次"是否带套装词条"）。
- 不碰 `battle.lua` / `equip.lua` 公式，不碰 combat 回合逻辑。

## §2 宝石（`gem.py`，≤150 行）

**数据**：`assets/gems.txt`，四段 `key|名称|属性|数值|每级增幅`，属性只用白名单内已有的
`atkflat / defflat / hpflat(新增) / crit / critdmg / leech / dodge`。

**碎片与合成**
- 碎片一种通用：`shard`（int，进存档，**不占背包格**，理由见 §0 表最后一行）。
- 合成：`3 碎片 → 1 颗 1 级随机宝石`；`3 颗同级同种 → 1 颗高一级`（上限 5 级）。
- 合成是"同种同级"三合一，**不是**随机赌——随机只发生在碎片开宝那一步，且只决定"哪种"，不决定"成败"。

**镶嵌**
- 孔位随物品走：`item["holes"] = 0/1/2`（白/蓝/紫，与 `AFFIX_COUNT` 同构），`item["gems"] = [key 或 ""]`。
- 镶嵌写入 `item["gems"][i]`，同一物品同一宝石不许重复（简单规则，避免叠乘爆炸）。
- 拆卸：宝石原样退回、孔位清空、**无损免费**。

**数值汇总**：`gem.bonus(equipment) -> dict`，返回与 `gear.totals()` 同构的
`{atk, hp, def, dodge, crit, critdmg, leech}`，由 `totals()` 在**词条之后、乘区之前**并入。

## §3 套装（`sets.py`，≤150 行）

**数据**：`assets/sets.txt`，`set_key|套装名|槽位列表(逗号分隔)|2 件效果|4 件效果`。

- 判定口径：`sets.active(equipment)` 统计每套已穿戴件数，≥2 触发 2 件效果、≥4 触发 4 件效果（**4 件不叠 2 件**，二者互斥取高）。
- 槽位只有 5 个（`gear.SLOTS`），所以一套最多 5 件；4 件套意味着"差一件就散"，这是设计上的取舍点，见 G7。
- 套装件怎么来：`gear.generate()` 出紫装时按种子掷一次"是否套装件"（概率进 `game.ini [set] drop_pct`），**不改**现有品质概率。
- 汇总：`sets.bonus(equipment) -> dict`，结构与 `gem.bonus` 相同，`totals()` 里与宝石**相加**后统一进乘区。

## §4 属性点（`attrs.py`，≤100 行）

**四维**（进 `game.ini [attr]`）：`atk_flat`（每点 +攻击）、`hp_flat`（每点 +生命）、
`def_flat`（每点 +防御）、`crit_pct`（每点 +暴击率，万分位，避免浮点累加误差）。

- 升级得点：`points_per_level = 3`，玩家**等级 2 起**每级给 3 点（Lv.1 不给）。
- 分配：`spent = {atk: n, hp: n, def: n, crit: n}`，`free = total - sum(spent)`。
- **免费无限洗点**：一键清零 `spent`，点数全额退回 `free`。
- 生效：`attrs.bonus(player) -> dict`，并入 `tot.atk / tot.hp / tot.def / tot.crit`，**在宝石套装之后**。
- **零影响红线**：`spent` 全 0 时 `attrs.bonus` 必须返回全 0，`apply_gear` 结果与 V2.9 **逐字节相同**（门禁断言，见 §7）。

## §5 schema 12 与迁移

新增四字段（全部有真实使用点，无预留）：

| 字段 | 类型 | 默认 | 使用点 |
|---|---|---|---|
| `shard` | int | 0 | 碎片计数（不占背包） |
| `attr` | dict | `{"spent": {"atk":0,"hp":0,"def":0,"crit":0}}` | 加点/洗点 |
| `gems` | list | `[]` | 背包里的宝石（`"key:lv"` 字符串，与 `inventory` 同构，占格） |
| `set_seen` | list | `[]` | 已见过的套装 key（图鉴/掉落提示用，纯记录） |

孔位与镶嵌**不进新字段**——直接长在装备 dict 上（`holes` / `gems`），跟着 item 一起进出背包，
天然支持"换下来的装备宝石还在上面"。老档旧装备没有 `holes`：`_migrate` **不改动已有 item**，
而是在 `gem.holes_of(item)` 里按品质**读取时补算**（`holes_of` 返回 `item.get("holes", AFFIX_COUNT[quality])`），
避免迁移时遍历背包改写物品（改写会污染历史掉落记录）。

`SCHEMA = 12`，`_migrate` 用 `setdefault` 逐字段补默认，旧值一字不动；v11→v12 单独一条门禁实测。

## §6 数值与基线的硬约束（本期最大风险）

**红线：不主动投入 = 数值不变。**

- 宝石要碎片合成才有，属性点要玩家手动分配才生效，套装要恰好穿够件数才有加成。
- 因此 **CLI 全通脚本（不碰宝石/加点）的 Lv.25 / 金币 798 必须原样不动**——这是本期的第一道验收，
  也是唯一能证明"三层加成没有偷偷生效"的证据。若跑了发现数值变了，说明有一层没做"opt-in"，立即回退查因。
- 若未来要让全通脚本主动投入（例如"带宝石全通"作为新基线），必须**单独立项**并显式重钉，
  不能在本期顺手改断言。

## §7 门禁（`smoke_v30a`，八项）

1. **零影响**：`spent` 全 0、无宝石、无套装时，`apply_gear` 输出与 V2.9-D2 逐字段相同。
2. **宝石单层**：镶嵌 1 颗攻击宝石，面板攻击精确 +N；拆卸后精确回落。
3. **宝石合成**：3 碎片 → 1 颗；3 同级同种 → 高一级；上限 5 级不吃 6 级。
4. **套装阈值**：1 件无效果、2 件触发 2 件套、4 件触发 4 件套且**不叠**2 件效果。
5. **属性点**：升级给点正确、分配生效、洗点全额退回且面板回落、点数为 0 时拒绝分配。
6. **UI**（offscreen 真窗口）：成长窗三页可打开、镶嵌/拆卸/加点/洗点各走一次并写档。
7. **v11→v12 迁移**：四新字段就位、旧值一字未动、已有装备不被改写；`validate` 十九项全绿。
8. **行数纪律 + 全链**：新模块与受影响模块不超预算；`v20→v29d2` 全链回归全绿。
