## 1. 角色成长（Lv.1~30）

### 1.1 经验曲线

```
exp_needed(lv) = round(60 × lv^1.65)
```

| 等级 | 2 | 5 | 10 | 15 | 20 | 25 | 30 |
|---|---|---|---|---|---|---|---|
| 升级所需 | 187 | 785 | 2,683 | 5,318 | 8,575 | 12,391 | 16,715 |

累计到 30 级约 18.8 万经验——由怪物经验与任务奖励反推校准（见 §3/§4）。

### 1.2 属性框架

| 属性 | 来源 | 说明 |
|---|---|---|
| 攻击 ATK | 角色 + 武器 + 词条 | 伤害主属性 |
| 防御 DEF | 护甲系装备 + 词条 | 减伤 |
| HP / MP | 角色基础 + 装备 | 归零判负 / 技能消耗 |
| 暴击率 / 暴伤 | 词条 + 被动 | 默认 5% / ×2 |
| 命中 / 闪避 | 鞋子 + 词条 | v2.2 启用，先给数据位 |
| 吸血 | 仅词条（紫色限定） | 按造成伤害回血 |

### 1.3 战斗公式（battle.lua 扩展）

```
最终伤害 = max(1, ATK × 技能倍率 × random(0.95~1.05) − DEF × 0.6)
暴击伤害 = 最终伤害 × (2 + 暴伤加成)
```

- 命中判定：命中率 = 95% + 命中 − 闪避（下限 60%）
- 逃跑成功率 = 50% − boss 战 0%

## 2. 装备系统（白/蓝/紫 × 5 部位 + 无级别）

### 2.1 品质规则

| 品质 | 基础值倍率 | 随机词条数 | 掉落来源 |
|---|---|---|---|
| 白 | ×1.0 | 0 | 普通怪 / 副本普通难度 |
| 蓝 | ×1.4 | 1 | 精英怪 / 副本精英难度 |
| 紫 | ×1.9 | 2 | 副本噩梦难度 / 隐藏 boss |

### 2.2 五部位与基础值公式（白装基准，随物品等级 lv）

| 部位 | 主属性公式 | 说明 |
|---|---|---|
| 武器 | ATK = 5 + lv × 3 | 唯一攻击来源大户 |
| 头盔 | HP = 30 + lv × 8 | |
| 护甲 | DEF = 2 + lv × 1.5 | |
| 腰带 | HP = 15 + lv × 4 ；DEF = 1 + lv × 0.5 | 双属性 |
| 靴子 | 闪避 = 3 + lv × 0.4 %；速度占位 | v2.2 速度生效 |

**蓝/紫 = 白装基础值 × 品质倍率 + 词条。** 所有公式住在 `scripts/equip.lua`，引擎永远不算装备数值。

### 2.3 随机词条池（affix pool，数据表 affixes.txt）

| 词条 | 数值区间 | 限制 |
|---|---|---|
| 攻击 +X | lv × (1.2~1.8) | 任意部位 |
| 攻击 +X% | 3~8% | 武器/腰带 |
| HP +X% | 4~10% | 头/甲/腰 |
| 防御 +X | lv × (0.4~0.8) | 甲/腰/靴 |
| 暴击率 +X% | 2~5% | 武器/头/腰 |
| 暴伤 +X% | 10~25% | 武器/靴 |
| 吸血 +X% | 2~5% | **仅紫装武器** |
| 经验加成 +X% | 5~10% | 头/腰 |

规则：同件装备词条不重复；紫装第二条词条数值至少取区间中位（保底不歪）。

### 2.4 无级别武器（全游戏唯一）

**「如意金箍棒·无级」**

- **Lv.1 即可装备**，无视一切等级限制
- 攻击不按物品等级算，按**持有者等级**成长：`ATK = 10 + 持有者Lv × 6`（30 级时 = 190，碾压一切紫武同级值）
- 固定 3 词条：吸血 5% + 暴伤 +25% + 暴击率 +5%（满值，不可重随）
- 获取：**唯一掉落**——第 10 幕隐藏 boss「六耳猕猴」（1% 掉率）或主线终章隐藏任务「真假美猴王」必得（二选一设计：刷子路线 or 剧情路线）
- 程序意义：装备系统必须支持"成长型装备"特例——实现时用 `scaling: owner` 字段与普通公式分叉，**检验数据驱动架构的弹性**

## 7. 工程扩展（架构侧不动摇的部分）

1. **数据表全套外置**：`items.txt / affixes.txt / loot.txt / quests.txt / maps.txt / skills.txt`——引擎代码 v1 之后再新增 ≤200 行系统代码，其余全是数据
2. **存档 schema 版本化**：`save.json` 带 `"schema": 2` 字段 + 迁移函数（v1 存档必须能升上来）
3. **数值校验脚本 `validate.py`**（P0）：检查每把武器有掉落来源、每任务奖励物品存在、经验曲线单调递增——**数据驱动世界的编译器**
4. **battle.lua 状态化**：从纯函数升级为"输入战斗状态 JSON → 输出新状态"，支撑 CD/连击/闪避 buff
5. **测试**：pytest 覆盖公式层（伤害边界/升级跨级/词条极值），引擎不再靠手打验收
