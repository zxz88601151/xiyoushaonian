## 0. 范围一句话

通关之后游戏不结束：无底洞无限层检验数值上限；无级别武器作为"成长型装备"特例
检验数据驱动架构弹性；validate.py 把数据表当源码编译——数据错了直接红。

## 1. 无级别武器「如意金箍棒·无级」（蓝图 §2.4）

| 项 | 规则 |
|---|---|
| 标识 | 装备字段 `scaling: "owner"`；普通装备无此字段即按 Lv 算（**旧档无需迁移该字段**） |
| 攻击（蓝图原话） | `ATK = 10 + 持有者等级 × 6`（Lv.1=16，Lv.30=190），**每次 apply_gear 重算**，不写死进 item |
| 主属性其它项 | hp/def/dodge 全 0（它只是一根棒子） |
| 词条（蓝图原话） | 固定三条满值：吸血 5% + 暴伤 25% + 暴击率 5%，**不掷骰、不可重随** |
| 强化 | 照常吃 `enh` 倍率（主属性 ×(1+0.05×enh)），与 V2.4 无缝衔接 |
| 获取（**OD-V25-01 已定：双轨都要**） | ① 剧情线：隐藏任务「真假美猴王」（h2，前置 = 通关第 10 图）完成后**必得**——可验收、不靠运气；② 刷子线：第 10 图 boss 六耳猕猴 `weapon:2:1` 进 [loot.boss] **1% 掉率**，测试用注入 rng 验证。两条路径各实测一次（门禁 §6.2） |
| 程序意义 | 检验"成长型装备"特例：**gear.totals() 需要 owner 等级入参**，是本期架构上唯一的有意破例 |

实现要点：`gear.totals(equipment, owner_level)`；engine.apply_gear 把 player["level"] 传进去。
gui_bag 的"装备加成合计"同步传等级，否则面板数字与实战不一致。

## 2. 无底洞爬塔（蓝图 §6「难度爬塔」）

| 项 | 规则（本期定） |
|---|---|
| 入口（**OD-V25-03 已定**） | **通关一次后解锁**：大厅出现「无底洞」按钮 + CLI 通关结算后询问进不进；未通关过则按钮隐藏（存档 week ≥1 或 tower_best >0 视为解锁） |
| 层数即等级 | 第 N 层怪物等级 = N，30 层后仍可继续（无限层 = 数值曲线压力测试） |
| 怪物数值（本期定） | 复用现有怪物模板 × 层数系数：`hp = 30 + N×18`、`atk = 6 + N×2.2`、`exp = 20 + N×12`、`gold = 10 + N×5`（住 tower.py，不硬编码在战斗里） |
| 战斗 | 复用 combat.battle（同一套流程/技能/逃跑规则）；boss 层每 10 层一次（逃跑必失败规则照旧） |
| 存档 | schema **7**：新增 `tower_best`（历史最高层）+ `tower_layer`（本次所在层，支持续爬）；旧档 v6→v7 补默认 0 |
| 奖励（本期定） | 每胜一层：金币入账 + 经验入账；每 5 层掉落一次（复用 loot.roll，怪物 key = `tower`） |
| 退出 | 死亡或主动撤离 → 回到大厅，本次层数清零，`tower_best` 保留 |
| 金币闭环 | 爬塔是金币主要产出，强化/商店/仓库扩容是去处——validate 每期对账（SUPPLEMENT §2.4） |

## 3. 数值平衡（本期三件事）

| # | 项 | 规则（本期定） |
|---|---|---|
| 1 | 等级上限 | **30 级封顶**，battle.lua levelup 不再无限升（蓝图技能表止于 Lv.30） |
| 2 | 经验曲线 | 蓝图给的 `need = 60 × lv^1.65`（住 battle.lua），替代现在的固定 100/级 |
| 3 | Lv.1 开局 | **OD-V25-02 已定：本期不做**，只做前两件（30 级封顶 + 经验曲线）。Lv.1 开局及其十图重平衡留 V2.6——本期把"封顶 + 曲线"先钉死，V2.6 才有稳定的平衡基线 |

平衡手法：不开新模块，**用脚本跑数证明**——`gm setlevel 30` + 发满配装备 → 脚本化爬 30 层，
要求满配 30 级能通 30 层不死；另跑一次 CLI 全通（不改数值）看自然流程最终等级落在哪，
作为 Lv.1 开局方案的决策依据。跑数结果写进本期验收记录，不靠嘴说"应该能过"。

## 6. 出口验收（七门禁）

1. **无级武器数值**：Lv.1 时 ATK=16、Lv.30 时 ATK=190（脚本改等级实测自动重算）；
   三词条满值固定；装备后 apply_gear 与背包面板数字一致
2. **无级武器获取**：决议路线全程实测一次（隐藏任务 done → 发武器 / 注入 rng 掷中 1%）
3. **爬塔**：脚本化连打 1→30 层，层号=怪物等级、每 5 层掉落、金币经验入账正确；
   死亡后 tower_best 保留、本次层数清零；续爬从 tower_layer 继续
4. **30 级满配通 30 层**（蓝图出口验收）：gm setlevel 30 + 满配 +10 装备 + 无级武器，
   脚本化爬到 30 层不死
5. **等级与曲线**：升到 30 级封顶不再涨；need 按 60×lv^1.65 单调
6. **validate.py 七项全绿**，并接进门禁
7. **回归**：smoke_v22/v23/v24 + CLI 全通仍绿（CLI 全通金币 918 若因爬塔/掉落改动变化，
   需在此显式重定基线，不许静默改判据）

- 音效、联网/多人、内购抽卡：红线不变
- 爬塔不做排行榜、不做赛季、不做每周重置

## 9. 决议带来的补充约定

1. 双轨获取的两条路径**共用同一个发放函数**（gear 里构造无级武器），禁止两处各写一份属性——
   与"共享函数改一处根因"同一条纪律。
2. 1% 掉率走现有 loot 表机制（`[loot.boss]` 增加一项），**不新增特殊分支**；
   loot 掷到无级武器时若已持有则不再重复发放（幂等，避免刷子刷出一背包棒子）。
3. 隐藏任务 h2 走 V2.2 既有 hidden 类型（前置 = 通关第 10 图 → map 事件触发激活 → 完成必得），
   不新造状态机分支。
4. Lv.1 开局不做，则 game.ini 的 `player.level=14` **本期不动**；
   经验曲线改为 60×lv^1.65 后，CLI 全通的自然等级会变，门禁基线按 §6.7 重定，不许静默改判据。
